# ปุ่มเรียนรู้ในแชตส่วนตัว — ขั้นเดโม

## สิ่งที่เพิ่มและเหตุผล

1. `main.py` วิเคราะห์เหมือนเดิม แล้วเรียก `build_lesson` ซึ่งสร้างบทเรียนเฉพาะผล risk_found ที่มี is_scam=true และมีเหตุผล ไม่เพิ่มปุ่มให้ no_risk_found, uncertain, คำทักทาย สื่อที่ไม่รองรับ หรือ error
2. `learning.py` จัดบทเรียนจากเหตุผลเดิมและคำที่ปรากฏจริง เลือกคำแนะนำไม่เกิน 3 หัวข้อ คำเหล่านี้ใช้เลือกเนื้อหาการเรียนรู้เท่านั้น ไม่เปลี่ยนผลวิเคราะห์ และไม่อ้างว่าคำใดคำหนึ่งพิสูจน์ว่าเป็น Scam
3. `LessonStore` สร้างรหัสสุ่มต่อเคส เก็บเจ้าของและข้อความบทเรียน ไม่เก็บข้อความต้นฉบับทั้งก้อนหรือ reply token เพิ่ม เหตุผลในบทเรียนอาจมีข้อมูลจากข้อความ จึงถือเป็นข้อมูลส่วนตัวเช่นกัน
4. `messaging.py` ส่งข้อความผลตรวจเดิมพร้อมการ์ด Buttons template ในคำขอ reply เดียว ปุ่มมี postback.data เป็น `learn:<รหัสสุ่ม>` ไม่ฝังข้อความหรือ user ID
5. เมื่อกดปุ่ม LINE ส่ง PostbackEvent มาที่ webhook เดิม ตรวจลายเซ็น โครงสร้าง event และ userId ให้ตรงเจ้าของก่อนตอบ ไม่เรียก AI/Vector ซ้ำ

อ้างอิงรูปแบบปุ่ม: https://developers.line.biz/en/reference/messaging-api/nojs/#buttons-template
และ postback: https://developers.line.biz/en/reference/messaging-api/nojs/#postback-action

## ข้อจำกัดที่ตั้งใจไว้

- บทเรียนเป็นเหตุผลจากผลเดิม + คำแนะนำตามหัวข้อ ไม่ใช่คำอธิบายใหม่จาก AI หรือผลยืนยันข้อเท็จจริง
- ใช้หน่วยความจำ process เดียว ต้องรัน worker เดียว รีสตาร์ต/--reload แล้วเคสหาย
- เคสเปิดได้ไม่เกิน 15 นาที สูงสุด 1,000 เคส; ล้างรายการหมดอายุเมื่อมีการเพิ่มหรืออ่านเคสครั้งถัดไป ไม่ใช่การลบตรงวินาทีที่ครบเวลา
- ถ้าเต็ม ไม่สร้างปุ่มใหม่ แต่ผลตรวจยังตอบได้ตามเดิม; ไม่ลบเคสที่ปุ่มยังใช้งานได้เพื่อรับเคสใหม่
- กดเคสหมดอายุ ไม่มีเคส หรือผิดเจ้าของ ได้ข้อความทั่วไปแบบเดียวกัน ไม่เปิดเผยเนื้อหา
- group/room ไม่สร้างปุ่มและไม่ตอบ postback เรียนรู้ แม้ผู้กดเป็นเจ้าของเคส
- webhookEventId ซ้ำยังใช้ EventGuard เดิม; การกดใหม่จริงสามารถอ่านบทเรียนเดิมได้โดยไม่เพิ่มค่าใช้ AI
- ยังไม่เพิ่ม MINI App, Dashboard, Dataset, ฐานข้อมูลถาวร หรือปุ่มลองใหม่
- ชุดทดสอบจำลองไม่ยืนยันว่าปุ่มแสดงบนอุปกรณ์จริงหรือผล Gemini แม่นยำ ต้องลอง LINE จริงก่อนเดโม

## ทดลองร่วมกันหลัง restart

1. ทัก `สวัสดีครับ` ในส่วนตัว: มีคำแนะนำ ไม่มีปุ่มเรียนรู้
2. ส่ง `รับงานออนไลน์ รายได้วันละ 1,500 บาท ก่อนเริ่มโอนค่าประกัน 300 บาท แล้วคืนพร้อมค่าจ้าง`: เมื่อได้ผล risk_found ต้องมีปุ่ม
3. กดปุ่ม: บทเรียนมีเหตุผลเดิมและคำแนะนำประกอบ ไม่มีการเรียก LLM/Vector ใหม่ใน log
4. ส่งอีกข้อความ เช่น `ส่ง OTP มาให้หน่อย`: กดปุ่มของเคสก่อนหน้าอีกครั้ง ต้องไม่กลายเป็นบทเรียน OTP ของเคสใหม่
5. ส่งคำเตือน `อย่าหลงเชื่อข้อความที่ขอ OTP อย่าส่งรหัสให้ใคร`: หากผลเป็น no_risk_found ต้องตอบผลตามเดิมโดยไม่มีปุ่มเรียนรู้
6. ส่ง URL อย่างเดียว: เมื่อผล uncertain ต้องแจ้งข้อมูลไม่พอโดยไม่มีปุ่มเรียนรู้ และไม่อ้างว่าเปิดตรวจปลายทาง
7. รีสตาร์ตแล้วกดปุ่มเก่า: แจ้งเปิดบทเรียนไม่ได้ ไม่เดาเคสใหม่
8. กลุ่มปกติ: ข้อความทั่วไปยังเงียบ ข้อความเข้าเกณฑ์ยังเตือน ไม่มีการ์ดเรียนรู้
